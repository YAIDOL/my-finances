# Фінансовий помічник

Розділ «Ще → Фінансовий помічник» містить локальний план на день, тиждень або решту місяця та чат NVIDIA `z-ai/glm-5.3-flash`. Планувальник працює без AI. Чат потребує окремої згоди користувача й серверного секрету.

## Увімкнення NVIDIA

1. Відкличте ключ, який був надісланий у чат, і створіть заміну у своєму NVIDIA API Catalog. Новий ключ вводьте безпосередньо в Supabase, не в повідомлення чи код.
2. Відкрийте [Edge Functions → Secrets](https://supabase.com/dashboard/project/jokedjcqioxifqyeghxe/functions/secrets) проєкту `my-finances` і збережіть секрет **NVIDIA_API_KEY** зі значенням нового ключа. Це секрет Edge runtime; префікс `VITE_` заборонений. Ніколи не додавайте його до GitHub variables, Pages, вихідного коду, URL або SQL.
3. Розгорнута `finance-chat` читає секрет під час запиту; повторна публікація сайту не потрібна. Увійдіть на сайт, відкрийте помічника, надайте згоду й надішліть тестове запитання. До налаштування сервер повертає `AI_NOT_CONFIGURED`, а сайт пояснює причину.

Підключення Supabase MCP не має інструмента запису Edge Secrets. На прохання власника NVIDIA_API_KEY встановлено через офіційний Dashboard зі вказаного локального файла; значення не потрапляло у вихідний код, Git або frontend. Доступність моделі та квота NVIDIA залежать від акаунта провайдера.

## Межі доступу

Браузер надсилає лише повідомлення `user/assistant`, згоду та очікуваний ID власника до Edge Function. Сервер перевіряє bearer через `auth.getUser`, відхиляє анонімний або інший акаунт, перевіряє існування сеансу й читає `finance_state` через користувацький JWT з RLS. Привілейований клієнт викликає лише RPC лімітування. Gateway `verify_jwt=false` дозволяє сучасні ключі підпису, але перевірка Auth усередині функції обов’язкова.

NVIDIA отримує системну інструкцію, скорочене зведення та до 12 повідомлень. Зведення містить загальні суми в копійках, назви категорій, витрати/ліміти й точні плани. Назви рахунків/цілей, номери карток, ID, імена боржників, нотатки та повний документ не передаються. Текст, введений самим користувачем, передається після згоди; UI це пояснює. Історія живе лише в пам’яті сторінки, не в нашій базі чи localStorage. Очищення не відкликає вже передані провайдеру дані.

Фіксовані HTTPS endpoint і модель, до 1000 символів користувача, 16000 загалом, 32768 байтів запиту, 65536 байтів відповіді провайдера, 2048 output tokens, До 120 секунд очікування генерації. Для чату задано chat_template_kwargs: reasoning_effort=low, clear_thinking=true; внутрішні міркування не відображаються. Реальний короткий запит до NVIDIA тривав 56–65 секунд, тому початкові 45 секунд були замалі. UI відображає звичайний текст без HTML, автоматичних посилань, інструментів або виконання коду. Відповіді AI можуть помилятися; суми й рішення слід перевіряти. Скасування відкидає пізню відповідь, але не гарантує скасування вже обробленого запиту/списання квоти провайдером.

Міграція `20261018203806_finance_ai_private_quota.sql` створює приватні таблиці без політик доступу й атомарний RPC лише для service_role: **6 запитів/хв, 30/добу на користувача, 200/добу на проєкт (UTC)**. Відмови провайдера також витрачають квоту. Лічильники не містять повідомлень чи фінансових даних. Користувацький рядок каскадно стирається при видаленні акаунта; глобальний лічильник знеособлений. Це обмежує використання, але не замінює контроль бюджету/доступу в NVIDIA та Supabase.

Наш код не логує ключі, фінансове зведення, JWT, повідомлення чи сирі помилки. Платформні журнали Supabase/NVIDIA керуються їхніми правилами; відсутність логування в нашому коді не є обіцянкою відсутності журналів у провайдера.

## Точні плани

План використовує актуальні внесені гроші, резерви цілей/платежів, регулярні витрати й непокриті борги. Майбутні записані кредити/надходження не фінансують витрати сьогодні; уже внесені майбутні списання враховуються консервативно. Очікувана зарплата й дебіторська заборгованість не додаються. Горизонт покриває більший із періоду плану та часу до наступного надходження (або решти місяця). Пропорції розраховані цілими копійками з точним розподілом залишку.

Місячний попередній перегляд показує **вже витрачено + додаткова дозволена сума**. Застосування замінює поточні місячні ліміти, зберігає інші місяці та не змінює рахунків/операцій/резервів. Нульовий кінцевий ліміт означає відсутність ліміту відповідно до моделі бюджету; це явно пояснено в перегляді. Потрібне ручне підтвердження. Застарілий, змінений чи вчорашній план відхиляється; збереження використовує звичайний owner/version RPC і підтримує скасування. Текст AI не може застосувати зміни.

## Розгортання та перевірка

Після міграції виконайте `supabase functions deploy finance-chat --project-ref jokedjcqioxifqyeghxe` з кореня репозиторію. Функція імпортує спільні доменні модулі з `src/lib/` через явні `.ts`, щоб сервер і сайт користувалися однією математикою. Додайте всі транзитивні залежності при розгортанні через API. Секрет встановлюється окремо через офіційний [Dashboard/CLI](https://supabase.com/docs/guides/functions/secrets).

Перевірки: модульні тести planner/server/provider/transport; `supabase/tests/finance_ai_quota.sql` виконує перевірки ACL, сеансу, меж лімітів, скидання вікон і каскадного видалення у транзакції з ROLLBACK. Хмарна перевірка синтетичним акаунтом підтвердила відмови без Auth/згоди, чужому власнику/origin та явний `AI_NOT_CONFIGURED`; тестовий акаунт видалено. Фінанси реальних користувачів не змінювалися.

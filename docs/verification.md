# Перевірка реалізації

5 жовтня 2026 року.

## Локальна перевірка

- 51 автоматичний тест: цілі копійки, залишки, перекази, відкладення, позики, повернення боргу, платежі, архівування, редагування та перевірка резервних копій.
- Валідація ніку, мінімум 6 символів пароля, індикатор надійності, клієнтська межа Supabase API.
- TypeScript без помилок; production-збірка Vite успішна.
- Браузер: додавання витрати, точний перерахунок балансу, відмова при нестачі грошей із повідомленням усередині діалогу, редагування суми й оновлення підсумків.
- Світла й темна тема; мобільний екран 390 × 844, меню основних і додаткових розділів. Горизонтального переповнення немає. Помилок у консолі не виявлено.
- Декоративна ілюстрація має плавний цикл руху; після ввімкнення «Зменшити анімації» обчислена animationName = none.
- Незалежний огляд коду: чотири знайдені проблеми виправлені; повторний огляд підтвердив виправлення.

## Реальна база Supabase

Проєкт `my-finances`, регіон eu-central-1, організація YAIDOL's Org. Міграція `finance_initial_schema` застосована; у profiles, finance_state, user_preferences ввімкнено RLS. Підтвердження email вимкнено після явного погодження користувача; стандартний мінімум 6 символів підтверджено справжньою реєстрацією.

Перевірено через публічний Supabase API на двох тимчасових тестових користувачах:

1. Реєстрація з паролем рівно 6 символів повертає активний сеанс.
2. Фінансовий документ записується атомарно.
3. Другий користувач не бачить фінанси або профіль першого.
4. Анонімне читання та запис фінансів заборонені.
5. Прямий UPDATE фінансової таблиці заборонений.
6. Два конкурентні збереження однакової версії дають одного переможця та один конфлікт.
7. Конкурентні перші збереження також не перезаписують одне одного.
8. Вихід і повторний вхід працюють; дані та версія зберігаються між сеансами.
9. У браузері вхід із ніком у верхньому регістрі відкрив правильний профіль. Витрату 10,25 грн записано через форму, перерахунок і її збереження після перезавантаження підтверджено.

Два тимчасові QA-облікові записи та їхні вигадані фінанси видалено після завершення перевірки; облікові дані тестів не потрапили в репозиторій.

Advisor попереджає, що авторизовані користувачі можуть викликати SECURITY DEFINER-функцію save_finance_state. Це навмисний єдиний шлях запису: функція використовує тільки auth.uid(), не приймає чужого user_id, перевіряє версію та має фіксований порожній search_path. [Опис перевірки Supabase](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).

## Межі поточної версії

Усі операції додаються вручну. Банківської синхронізації немає. Картки зберігають назву й останні чотири цифри, без повного номера. Нік унікальний і нечутливий до регістру. Відновлення пароля через email недоступне для входу тільки за ніком.

Тема, приховування сум та інтенсивність анімацій зберігаються на конкретному пристрої. Демо має вигадані дані й тримає зміни лише протягом відкритого сеансу. Шаблони операцій, користувацькі категорії, історія поповнень цілей та складні порівняння періодів залишаються можливим наступним розширенням.

## Публікація

Код опубліковано в YAIDOL/my-finances. GitHub Pages налаштовано на workflow; публічні Supabase URL і publishable key додано як repository variables. Перевірена збірка також доступна в окремій gh-pages гілці.

5 жовтня 2026 року GitHub повідомив про затримки призначення hosted runners. Основний workflow та резервний Pages build залишилися в черзі. Резервний build скасовано, джерело повернено до GitHub Actions для автоматичної публікації актуального коду після відновлення сервісу. Онлайн-адреса до завершення deployment повертає 404. [Інцидент GitHub Actions](https://www.githubstatus.com/).

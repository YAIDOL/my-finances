# Мої фінанси

[Відкрити сайт](https://yaidol.github.io/my-finances/)

[Детальний опис усіх розділів](docs/FEATURES.md) · [Результати перевірки](docs/verification.md)

Особистий менеджер фінансів українською: ручні витрати й надходження, картки та готівка, власні кольорові категорії, перекази, борги, цілі, бюджет і планові платежі. Стриманий графітово-синій дизайн, світла/темна/системна тема, адаптивність та плавні анімації з підтримкою reduced motion.

Меню «Ще → Для щодня» містить шаблони записів, повторювані платежі з підтвердженням, розрахунок доступної суми до наступного доходу та нагадування про борги й платежі. Останню підтверджену фінансову зміну можна скасувати в поточному сеансі. [Опис і перевірка нових інструментів](docs/daily-tools.md).

## Запуск

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
```

Без конфігурації Supabase доступне лише явно позначене демо. Реєстрація не підмінюється локальними обліковими записами. Паролі ніколи не зберігаються у фінансовій базі або резервних копіях.

## Supabase

Виконайте всі міграції з `supabase/migrations/` у порядку назв файлів, налаштуйте nickname-only Auth за [інструкцією](docs/SUPABASE.md) та заповніть `.env.local` за `.env.example`. Для frontend використовуйте тільки publishable або anon key. Secret/service_role key не повинен потрапляти у код або репозиторій.

## GitHub Pages

У Settings → Pages виберіть GitHub Actions. У Settings → Secrets and variables → Actions → Variables додайте `VITE_SUPABASE_URL` і `VITE_SUPABASE_PUBLISHABLE_KEY` (або legacy `VITE_SUPABASE_ANON_KEY`). Workflow `.github/workflows/pages.yml` перевіряє тести, збирає сайт і публікує `dist` після push у main.

Hash-навігація працює на GitHub Pages без серверного fallback. Відносні шляхи ресурсів підтримують розміщення у підкаталозі репозиторію.

## Дані

Усі суми зберігаються як цілі копійки. Кожен користувач має власний атомарний документ у Supabase з RLS і перевіркою версії, що запобігає тихому перезапису між вкладками. Невдала хмарна операція не підмінюється локальним збереженням.

Перекази не є доходом або витратою; відкладення залишаються частиною балансу; позики та повернення основної суми обліковуються окремо. Новий обліковий запис порожній. Рахунок створюється з нульовим балансом; додавання та списання грошей — окремі дії. Для готівкової операції можна вибрати лише готівковий рахунок. Категорії та кольори приватні для кожного користувача. Збереження підтверджує і версію, і очікуваного власника стану. Демо використовує виключно вигадані дані й тримає зміни в пам'яті поточного сеансу.
